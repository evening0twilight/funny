# 小红书平台参考：把一条 AI 新闻写成能发的小红书

> **这份文件解决什么问题**：给定一条 AI 新闻和一张素材卡，告诉运营标题怎么起、正文按哪种结构搭、AI 资讯号特有的坑怎么绕、发之前逐项对照哪些硬约束。
> 量化约束继承自 `cn-skills/xiaohongshu-post`（标题 ≤20 字、3 个备选、正文 300–800 字、段落 1–3 行、emoji ≤8、标签 5–8、禁 `**`、结尾一个 CTA、禁绝对化用语），但原文的种草/测评/教程结构**已整体换掉**——我们是 AI 资讯号，不是带货号，没有"自用三个月"这种素材。
> 本文件是写法参考，不是成品；`check_copy.py` 校验的对象是 `out/` 下的成品稿。

---

## 1. 先搞懂平台在拿什么给你打分

| 环节 | 平台看什么 | 对资讯号的含义 |
|---|---|---|
| 进不进流量池 | 封面 + 标题点击率 | 事件本身不稀缺，稀缺的是"**这跟我有什么关系**" |
| 进不进下一个池 | 前 3 行完读率 | 第一行必须已经在讲事，不能还在暖场 |
| 能不能二次分发 | 收藏 / 评论 / 关注 | 结尾只给**一个**动作，给两个等于没给 |

一句话：小红书不是"写一篇短文"，是三样东西一起做——**让人点进来**（封面 + 标题）、**让人读完**（开头三行）、**让人动手**（结尾一个动作）。

## 2. 硬约束清单（这些是验收标准，不是建议）

| 项 | 约束 | 为什么硬 |
|---|---|---|
| 标题 | **≤20 字**，给 **3 个**备选，覆盖不同公式 | 长标题在信息流里被截断，读不全就没点 |
| 正文 | **300–800 字**（`check_copy.py` 按汉字数算） | 超 800 完读率断崖式下跌 |
| 段落 | **1–3 行**一断，一屏不超过 4 段 | 手机上一整块文字等于劝退 |
| 开头三行 | 直接给结果或抛冲突；**禁止**"大家好我是XX" | 前三行决定完读率 |
| emoji | 每段 **≤1**，全篇 **≤8**，放段首当视觉锚点 | 堆 emoji 像广告号 |
| 排版 | **禁止** `**` 加粗和 `#` 标题语法 | 小红书不渲染 Markdown，发出来是原始符号 |
| 标签 | **5–8 个**：2–3 泛 + 2–3 垂类 + 1–2 自定义 | 泛标签给曝光池，垂类标签给精准人群，缺一不可 |
| 结尾 | 只给**一个**互动动作（收藏 / 提问 / 关注，选一个） | 动作一多，用户一个都不做 |
| 用词 | 禁绝对化用语（最强 / 第一 / 100% 这类） | 广告法高危，被投诉就是限流甚至处罚 |
| 事实 | 每个数字带主体和出处；未公布就写"截至 X 月 X 日未公布" | 评论区拆穿一次，账号就废 |

> 自检时逐项过 §6 的表，别凭印象。

## 3. 三种结构（资讯号专用，按选题类型选一种）

### 3.1 快讯型

> 下面三种结构里的正文示例是**节选**（为了展示骨架，字数不足 300）。实际发布必须补到 300–800 汉字，否则 `check_copy.py` 会判 FAIL——这是对的，别改检查器去迁就示例。

**什么时候用**：事件本身够大——发布、封杀、事故、融资、政策落地。读者的第一需求是"发生了什么"，不是"你怎么看"。

**开头三行怎么写**

1. 第 1 行：**主体 + 动作 + 时间**，一句话讲完事件，不铺垫。
2. 第 2 行：一个最有说服力的**数字**（对比数字优先，例如"成本只有上一代的三分之一"）。
3. 第 3 行：把它和读者接上——"对你意味着什么"或"为什么这条值得看"。

**正文骨架**

```
① 一句话说清事件（时间 + 主体 + 动作）
② 2–3 个硬指标，每个数字后面带口径（谁测的、什么榜）
③ 一个"但是"：限制条件、没公布的东西、适用范围
④ 谁适合 / 谁不适合
⑤ 一个提问收尾
```

**结尾钩子**：二选一式提问（"你更在意 A 还是 B"），让读者动手的成本最低。

**真实示例（素材：MiniMax M3.1 Flash）**

```
【标题】
1. MiniMax 新模型成本只要 1/3
2. 速度快 3 倍，价格只要 1/3
3. 等一下，M3.1 的许可证还没公布

【封面文案】
主文案（≤10 字）：成本砍到 1/3
副文案（小字）：速度约 3 倍，权重 10/23 开放

【正文】
MiniMax 在 10 月 19 日发布了 M3.1 Flash。官方给的两个数字很直接：成本是 M3 的三分之一，速度约 3 倍。🤖

硬指标也一起放出来了。生成速度 200+ TPS，也就是每秒两百多个 token；DeepSWE v1.1 拿到 73.7%，OSWorld V2 是 61.7，CyberGym 82。第三方评测 Artificial Analysis 给的智能指数是 42，比 M3 高 13 分。

价格按百万 token 算：输入 0.15 美元，输出 0.60 美元。对天天跑 Agent 的人来说，这个价位意味着可以把试错当日常操作，而不是每跑一次都精打细算。

但它不是没有软肋。权重 10 月 23 日才开放，许可证截至抓取日没有公布——能不能直接拿去做商用产品，要等那天才有答案。🤔

适合谁？想低成本跑长任务、又愿意等几天的开发者，以及预算卡得很死、又要天天跑 Agent 的小团队。不适合谁？现在就要签商用授权的人。

顺便记一句：这次值得留意的不是某个跑分，而是"同样的事变便宜了"这件事本身——去年要花钱试的活儿，今年可以敞开了试，尤其是本来就靠 API 吃饭的小团队和独立开发者。

你更在意 73.7% 这个跑分，还是 0.15 美元这个价格？

【标签】
#AI资讯 #人工智能 #大模型 #MiniMax #开源模型 #AI工具 #AI日报
```

### 3.2 解释型

**什么时候用**：政策、术语、看不懂的发布。读者不是不知道"有这事"，是不知道"这跟我有啥关系"。

**开头三行怎么写**

1. 第 1 行：把读者放进一个**具体场景**（"你天天用的那个工具……"）。
2. 第 2 行：点出那句让人看不懂的原文或术语，直接念出来。
3. 第 3 行：承诺这篇讲清什么（"三句话说清它管到哪"）。

**正文骨架**

```
① 原文/事件本身，先摆出来（不解释）
② 翻译成人话：它到底约束了谁、约束了什么
③ 影响：谁会被波及，谁今天不用慌
④ 留一句"但是"：范围、例外、时间窗口
⑤ 一个开放问题收尾
```

**结尾钩子**：开放问题（"你们公司会因为这类命令换工具吗？"），把评论区当第二篇稿子的素材。

**真实示例（素材：美国国土安全部命令移除 DeepSeek）**

```
【标题】
1. 联邦机构要移除 DeepSeek
2. 美国国土安全部发了道命令
3. 你用的工具可能在这份名单里

【封面文案】
主文案（≤10 字）：60 天，移除
副文案（小字）：范围包括"基于它开发的产品"

【正文】
美国国土安全部发了一道命令，要求联邦文职机构在 60 天内停用并移除 DeepSeek，以及基于它开发的产品。

依据是 2018 年的供应链法，命令编号 2026-01。原文范围值得逐字看：不只是 DeepSeek 自己的模型，还包括第三方用 DeepSeek 做出来的产品和服务。📌

翻成人话：受影响的首先是一批给美国联邦机构供货的工具商。按命令的字面范围理解，只要某个工具底层接了 DeepSeek，就可能被算进"基于其开发的产品"里——具体怎么认定，命令没细说。

命令里留了例外申请的口子。这句话别漏：不是一刀切，机构可以申请例外。所以后面大概率会有扯皮和延期，看到"已完成移除"的说法先别急着转。

对不碰美国联邦业务的人来说，今天不用做什么。但它说明一件事：模型来源正在被当成采购条件，而不只是技术选型。🤔

你们公司会因为这类命令换掉手上的工具吗？

【标签】
#AI资讯 #人工智能 #DeepSeek #AI政策 #科技新闻 #AI日报
```

### 3.3 预测型

**什么时候用**：有规律可循、或者有明确"对答案日期"的事。这类完播和互动最高，但**必须明说是预测**，并且给出对答案的时间点——否则就是造谣。

**开头三行怎么写**

1. 第 1 行：先把**结论**扔出来（"我的判断是……"）。
2. 第 2 行：给**依据**（一条硬信息就够，别堆）。
3. 第 3 行：给**对答案的日期**（"23 号就知道我猜得对不对"）。

**正文骨架**

```
① 结论一句话（写明"我的判断"）
② 依据 1–2 条，必须是公开可查的事实
③ 条件句：如果 X 成立 → 会怎样；如果 X 不成立 → 又会怎样
④ 对答案的日期 + 为什么值得等
⑤ 收藏式收尾（让读者回来找这条）
```

**结尾钩子**：收藏式（"23 号回来对答案"）。预测型不要用提问收尾，会把"等结果"的动作冲掉。

**真实示例（素材：M3.1 Flash 的许可证，10/23 开放权重）**

```
【标题】
1. 10/23 开放权重，许可证才是关键
2. 我的判断：许可证大概率不会缺席
3. 23 号回来对答案，先收藏

【封面文案】
主文案（≤10 字）：23 号见分晓
副文案（小字）：权重开放当天，许可证给不给

【正文】
先说结论：我的判断是，10 月 23 日开放权重那天，许可证大概率会一起给出来。

依据只有一条硬信息：官方把 10/23 这个日期说得很明确，但发布稿里对许可证一字未提。日期给死、条款留白，通常是法务流程还没走完，而不是不打算给。📅

如果 23 号两样一起给，这次就真的能直接拿去做产品，价格优势才算完整；如果只给权重不给许可证，那它更适合当研究模型用，商用还得再等——这两条路差别很大，值得单独盯。

不管哪种结果，23 号都是能对答案的日子。而且这个价位的模型，条款怎么写会直接影响你怎么用它，比跑分更值得看。

我会在那天回来更新结论，猜错了就在这条下面认。🤔

你觉得会一起给吗？先收藏，23 号回来对答案。

【标签】
#AI资讯 #人工智能 #大模型 #MiniMax #模型开源 #AI预测 #AI日报
```

## 4. AI 资讯号的小红书特有坑

### 4.1 技术名词怎么降维

**一条原则：把"它是什么"换成"它替你干什么"。** 术语留一个就够，多了读者直接划走。

| 不要这样写 | 这样写 |
|---|---|
| "在 DeepSWE v1.1 上取得 73.7%" | "一个考真实修 bug 能力的榜，它拿了 73.7%（满分 100）" |
| "开放权重" | "权重开放＝你能把模型下载到自己的机器上跑" |
| "TPS 200+" | "每秒能吐出两百多个 token，比你读完这行字还快" |
| "智能指数 42" | "第三方综合跑分 42，比上一代高 13 分" |
| "许可证未公布" | "能不能拿它做商业产品，现在还没答案" |

三个降维动作，按顺序做：
1. **找替身**：这个模型/功能替掉了谁的什么活儿。
2. **换单位**：换成钱（贵不贵）、时间（快不快）、门槛（我能不能用）。
3. **给场景**：一句"你点开就能用"的具体动作。

**别过头**：降维不等于失真。"能替你写代码"是降维，"程序员要失业了"是造谣——两句话之间隔着一个账号的信誉。

### 4.2 数字怎么排版

- **一段最多两个数字**，三个以上读者记不住，也显得像通稿。
- 数字可以单独占一行（资讯号可接受），但后面必须跟口径：「73.7% · DeepSWE v1.1」比裸写一个 73.7% 稳。
- **每个数字带主体**：官方说的写"官方称"，第三方评测写"据 XX 评测"，自己换算的写"按……折算"。
- **不要并排两个口径**：官方说"成本 1/3"、第三方说"定价一半"是两件事，分开归属，别合成"成本砍半"。
- 百分比和倍数选一个：写"成本是 1/3"就别再写"降低 67%"，两个说法一起上会显得在凑数。

### 4.3 竞品怎么提

- **只提"和谁比"，不写"谁不行"**。可以说"这个榜上它排在某某前面"，不要写"某某已经不行了"。
- **比较必须有口径**：有榜单/评测才比，并且写清"据 XX 评测"；没有口径就不比，只讲它自己做到了什么。
- **有出处才能用极限词**：即使引用的标题里有"最强"，正文也降成"这次领先在哪"——平台判的是你的稿子，不看你有没有出处。
- 涉及中美厂商对比时，只写事实与适用场景，不站队、不阴阳。评论区吵起来对流量有利，对账号长期不利。

### 4.4 预测怎么写条件句

- **三段式**：`如果 X → 那么 Y；如果 X 不成立 → 那就是 Z。`两条路都写，读者才信你不是在蒙。
- **必须给日期**：没有"对答案日期"的预测不要发，它只会变成一条软文。
- **禁止把预测写成事实**："将开放"（像官方口吻）→"我的判断是，大概率会给"。
- **一条笔记最多一个预测**。两个预测等于一个都不成立。
- 预测错了要回来改，并在评论区认——这是预测型账号唯一的护城河。

## 6. 发布前自检表（展开版）

**标题**
- [ ] 3 个备选，每个 ≤20 字（含数字、英文、空格都算）
- [ ] 至少一个是从读者视角写的（能看出"我能得到什么"）
- [ ] 没有标题党到和正文对不上（点进来发现不对，完读率会反噬）

**正文**
- [ ] 300–800 字
- [ ] 前 3 行已经在讲事，没有"今天来聊聊"
- [ ] 段落 1–3 行一断，一屏不超过 4 段
- [ ] 没有 `**`、没有 `#` 标题语法
- [ ] emoji 每段 ≤1、全篇 ≤8

**事实**
- [ ] 每个数字都有主体（官方 / 据 XX 报道 / 据 XX 评测）
- [ ] 未公布的信息写成"截至 X 月 X 日未公布"，没有写成"不会公布"
- [ ] 没有把转述压成官方口径
- [ ] 没有自己算的数冒充当原文

**结构与互动**
- [ ] 用了三种结构里的一种，不是三合一
- [ ] 结尾只有一个动作（收藏 / 提问 / 关注，选一个）
- [ ] 通篇没有"私信我""评论区扣 1""加微信"这类站外导流
- [ ] 没有编造体验（"我用了三个月"这类）

**合规**
- [ ] 无绝对化用语（最强 / 第一 / 100% 这类）
- [ ] 封面 / 内页图是 AI 生成的话，发布时勾选 AI 生成声明并加角标
- [ ] 标签 5–8 个，泛标签和垂类标签都有

**机器校验**

```bash
python3 skills/ai-news-content/scripts/check_copy.py out/<日期-事件>/01-小红书图文.md --material material.json
```

FAIL 必须清零再交；WARN 逐条在 §4 风险里写结论。

## 7. 失败案例：改前 vs 改后

| 改前（反面） | 问题 | 改后 |
|---|---|---|
| "今天来聊聊大模型圈的大新闻，最近真是太卷了" | 前 3 行全是暖场，完读率会掉光 | "MiniMax 在 10 月 19 日发布 M3.1 Flash，成本是 M3 的 1/3" |
| "这款模型堪称地表最强，实测碾压所有对手" | 绝对化用语 + 没口径 + 编造体验，三连违规 | "据 Artificial Analysis 的智能指数，它比 M3 高 13 分" |
| "开放权重啦！懂的都懂！快来私信我拿教程" | 站外导流 + 信息量为零 | "权重 10/23 开放＝你可以下载到自己机器上跑；商用要看许可证" |
| 正文 1200 字，把发布稿整段翻译 | 超 800 字断崖，且像通稿 | 砍到 400 字：事件 + 2 个数字 + 1 个"但是" + 1 个提问 |
| 标签只写 #AI #人工智能 | 全是泛标签，没有精准人群 | 泛标签 2 个 + 垂类 3 个（#MiniMax #开源模型 #AI工具）+ 自定义 1 个 |
| 结尾"点赞收藏关注评论转发" | 五个动作等于没有动作 | 只留一个："你更在意跑分还是价格？" |
