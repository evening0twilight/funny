# 数据来源与使用权：怎么「用数据」而不「抄表达」

> 这是给做内容的人看的实用版，不是法律意见。核心结论：**事实你可以用，别人的叙述不能照搬；商业化的边界比个人号紧。**

---

## 1. 先把三件事分开

| 层面 | 管什么 | 对你的实际影响 |
|---|---|---|
| **著作权法** | 保护「表达」，不保护「事实」和「思想」 | 「MiniMax 发布了 M3.1 Flash，成本是上代 1/3」是事实，谁都能写；但 AIHOT 那段 700 字的综述是它的**表达**，整段搬就是复制 |
| **站点使用条款** | 你和站点之间的合同 | 你一调它的 API，就等于接受了它的 terms。个人非商业免费；对外商业产品/客户交付/数据转售/公开镜像需书面授权 |
| **平台规则** | 小红书/抖音怎么判 | 搬运、洗稿、无来源、AI 未标识，都会被限流 |

三件事互相独立：**版权法上没问题，不代表不违反条款；条款没禁，不代表平台不判你搬运。**

## 2. 关于 AIHOT（以及其他聚合站）

用户的疑问很合理：「我们只是拿它的数据，又不是直接拿它的网站；而且 GitHub 上做 AI 热点的又不止一家。」

这个理解**大方向对，但要拆开看**：

**✅ 你可以自由用的**
- 事件本身：谁发布了什么、什么时候、什么参数、什么价格、什么反应
- 公开可查的数字与事实
- 你自己重新组织的叙述、判断、解读

**⚠️ 要小心的**
- AIHOT 的 `digest`（AI 综述）和 `reason`（推荐理由）是**它的编辑表达**。整段复制、稍改几个字再发，属于洗稿
- 把它整理好的内容做成付费产品（会员简报、知识库、付费社群）——这是条款里明确要授权的场景

**❌ 不要做的**
- 批量抓取后公开镜像/二次分发整个数据集
- 拿它的综述直接当自己的稿子（版权 + 平台判搬运，双重风险）

### 一个必须说清的区分：你「重写」和「复制」不是一回事

只要你是**读完原意、用自己的话重新组织、按内容需要扩写或精简**，产出就是你的表达——这已经在 L1 里，**不需要额外授权**。
真正要注意的只有两种情况：① 整段照搬它的文字；② 把它整理好的内容做成付费产品。

所以正常做号（个人号、娱乐向整活），**不用为这件事焦虑**，按 L1 走就行。

### 关于「API」这个词

技术上，`tools/aihot_fetch.py` 确实是调用 `aihot.news` 的公开 HTTP 接口取数据的——**没有 Key、不要账号、只读**，和你在浏览器里打开网页看是同一份数据。之所以文档里提「条款」，是因为用了接口就等于接受了站点规则；但规则本身写得很清楚：**个人非商业、公益、组织内部使用免费**。

换句话说：你做个人号、蹭梗、发图发文，**现在就在被允许的范围内**。只有当你开始接商单、卖课、做付费社群或对外产品时，才需要去问一句。

**实操结论（三档）**：

| 档位 | 做法 | 风险 |
|---|---|---|
| **L1 最稳** | 只取事实（数字/时间/主体/官方原话），用自己的话重写；重要事实回官方源核对 | 极低 |
| **L2 可接受** | 用 AIHOT 做导航和交叉验证，标注「资料来源：AIHOT」，不整段引用 | 低 |
| **L3 别做** | 整段搬运 digest、做付费产品卖它的整理成果、公开镜像 | 高 |

**什么时候该发一封邮件问一句**（wzglyay@virxact.com）：
- 账号开始接商单、带货、卖课
- 做付费社群 / 会员简报
- 做成对外产品（小程序、App、网站）
- 想批量使用或公开转载

个人号阶段，做到 L1 就够了。

## 3. 「GitHub 上还有别家在做」这件事

对，很多。但这解决的是**来源多样性**，不是**版权问题**。

- 换一个聚合站，你依然不能照抄那个站的文字
- 但你可以用它**交叉验证事实**，这恰恰是提高质量的办法
- 真正安全的做法是：**事实优先回到官方源**（厂商博客、官方 X、官方文档），聚合站只当「今天有什么值得看」的导航

这条对内容质量也是加分项：官方源往往有第一手的数字和原话，而聚合站的转述可能已经失真（我们实测就遇到过「1M 上下文」其实是第三方按 API 文档转述、官方没确认）。

## 3.5 一个容易误解的地方：`tier` 说的是「谁说的」，不是「从哪拿的」

素材卡里 `facts[].tier` 标的是**事实归属**：

- `official` = 这条说法的主语是厂商官方（「官方称成本为 1/3」），**不代表你的取材渠道是官方**
- 我们是从 AIHOT 的综述里读到这条「官方称」，所以：`tier=official` 但 `source=AIHOT AI 综述`、`tier_reason` 会写明判定依据

**为什么这很重要**：上一轮实测埋过两个坑——人民币价格、许可证状态。如果只看 tier 是 `official` 就当「官方确认」，等于把聚合站的转述合法化了。

**正确用法**：
- `tier` 决定你**怎么写**（能不能直接断言，还是要写「据 XX」）
- `source` 决定你**信不信**（聚合站转述的官方说法，最好回官方原链核一遍）
- 写稿时两者都要看：`tier=official` + `source=聚合站` → 写「官方称……」，但把原链打开确认一遍

## 4. 事实来源优先级（写稿时按这个顺序取）

| 优先级 | 来源 | 用法 |
|---|---|---|
| 1 | 厂商官方博客 / 官方 X / 官方文档 | 可以直接当事实写，最好带时间 |
| 2 | 一手媒体报道（记者采访、官方给了评论） | 写「据 XX 报道」 |
| 3 | 评测机构（Artificial Analysis、Arena 等） | 写「XX 评测显示」，注意评测口径和日期 |
| 4 | 聚合站（AIHOT、HN、Reddit） | 只当导航，不当事实来源 |
| 5 | 社交媒体传闻、匿名爆料 | 不写；或写「有说法称，未获官方确认」 |

## 5. 其他素材的使用权

| 素材 | 能不能用 | 注意 |
|---|---|---|
| 新闻事件本身 | ✅ | 事实不受版权保护 |
| 厂商发布会截图/官方图 | ⚠️ | 通常可作报道性使用，注明来源；商用要谨慎 |
| 别人的推文截图 | ⚠️ | 引用讨论可以，注意隐去个人信息 |
| 电影/剧集/游戏画面 | ❌ | 做视频 B-roll 用会侵权 |
| 他人的小红书/抖音视频 | ❌ | 搬运必限流，且侵权 |
| 字体 | ⚠️ | 商用字体另买授权；做卡片图注意 |
| BGM | ⚠️ | 用平台曲库，别从别处扒 |

---

## 6. 一句话记住

> **事实是公共的，叙述是私有的。**
> 你从任何地方拿到「发生了什么」，然后用自己的话讲「这意味着什么」——这条线以内，既安全，内容也更好。
