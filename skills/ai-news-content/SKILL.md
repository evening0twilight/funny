# AI 新闻内容工坊

一条 AI 新闻 → 六种成品（**整活梗图 / 整活视频** / 快讯 / 小红书 / 抖音 / 视频提示词）。

> **总原则：先让人停下来，再谈信息。**
> 没人点开的内容，事实再准也等于零。所以拿到来料，先问「这条能不能变成一个梗」（见 `references/08-meme-engine.md`），
> 再决定做成图还是视频、发小红书还是抖音。信息完整度排在注意力后面。
**输入不限于 AIHOT**：官方博客、任意新闻页、直接粘贴的一段文字都能吃；AIHOT 是默认且最省事的主力源。

> 这个 skill 由三个社区 skill 合并重构而成，不是简单拼装：
> - **cn-skills**（xiaohongshu-post / douyin-script）→ 吸收了它全部量化约束（标题 ≤20 字、正文 300–800 字、emoji ≤8、标签 5–8、语速 240–280 字/分、每句 ≤15 字）
> - **shuorenhua**（去 AI 味）→ 吸收「保住什么 / 怎么改」的判断逻辑，压成一页可执行清单（见 §6）
> - **lanshu-video-kit**（视频提示词）→ 吸收「图生视频只描述运动」「每镜一运镜」「不写死秒数」「显式端点」四条铁律
>
> 同时修掉了它们各自的坑：cn-skills 没有事实分层；shuorenhua 的完整版偏长且面向「改稿」而非「写稿」；lanshu 面向即梦/可灵 API，而用户实际在 **arcloop.ai** 上手动生成（见 references/arcloop-models.md）。

## 0. 什么时候用 / 不用

**用**：手上有一条 AI 新闻（或有链接、或有一段文字），要输出能发的东西。

**不用**：纯观点长文、深度评测、带货脚本、非 AI 领域的新闻。

## 0.5 路径规则（硬性，防串日）

**所有产出必须落在当天的文件夹里**：`out/YYYY-MM-DD/<slug>/`。
**素材卡放当天数据目录**：`data/raw/YYYY-MM-DD/<slug>/material.json`。

- 不许跨日复用 material（昨天的数据今天要用，复制到今天目录并注明原始出处）
- 开工先跑 `python3 tools/new_day.py`，以它打印的日期为准
- 收工跑 `python3 tools/doctor.py`，不通过不算完成

规则全文见项目根目录 `CONVENTIONS.md`。

## 1. 第一步永远是归一化输入

不要一上来就写。先跑：

```bash
# AIHOT 事件（最常用，信息最全：AI 综述 + 报道时间线 + firstParty 标记）
python3 skills/ai-news-content/scripts/prep_input.py --aihot-story <publicId> --out material.json

# AIHOT 今日热点榜
python3 skills/ai-news-content/scripts/prep_input.py --aihot-hot --out material.json

# 任意新闻页 / 官方博客
python3 skills/ai-news-content/scripts/prep_input.py --url https://... --out material.json

# 用户直接粘贴的一段文字
pbpaste | python3 skills/ai-news-content/scripts/prep_input.py --file - --out material.json
```

产物是一张**素材卡**，字段见 `references/input-adapters.md`。最要紧的是三个数组：

| 数组 | 用途 |
|---|---|
| `facts[]` + `tier` | 事实分层：`official` / `first-party` / `third-party` / `unverified` |
| `numbers[]` | 所有数字单独抽出来，写稿时逐个核对 |
| `quotes[]` | 原话，带说话人 |

> 拿不到 AIHOT 也能用：`--url` 和 `--file` 完全本地，不依赖任何站。
> 但**事实的最终来源优先厂商官方发布**，聚合站只是导航——这条见 `references/00-sourcing-and-rights.md`。

## 1.5 读热点注入：今天什么在火（整活必做）

```bash
cat data/hot-trends.md    # 存在就先读；不存在就问用户今天有什么热梗/赛事/新歌
```

每条热点按可信度标：✅ 已核实（官方页面/赛程/官宣） / 🟡 用户提供（可写但要复核） / ❌ 查不到（只借结构，不写具体数字）。
规则见 `references/10-trend-injection.md`。

**重要**：蹭赛事不等于伪造赛果。虚构队名的 13:0 随便做；真实队名的假比分绝对不做。

## 2. 选题判断：先决定值不值得做（30 秒）

开工前问三个问题，任何一个答「否」就换题：

1. **一句话说得清吗**？说不清就是事件太复杂，得先补背景（或者干脆等明天日报的综述）。
2. **跟你的观众有关系吗**？AI 资讯号的观众大体分三类：开发者/从业者、工具尝鲜用户、看热闹的大众。同一件事对三类人的价值完全不同。
3. **有画面吗**？纯政策、纯融资的题很难做视频，适合做图文卡；有对比、有数字、有"前 vs 后"的题才适合视频。

打分可以用 `python3 tools/topic_score.py --profile news|tool|opinion`。

**第四问（最重要）：这能变成一个梗吗？**
能 → 走 `meme` 模式，用 `references/08-meme-engine.md` 的三种机制（置换 / 对决 / 预告）去套。
不能 → 退回落 `flash`/`xhs`，别硬编。

**选题的三种合法姿势**（不要只会快讯）：
- **快讯型**：事件本身够大（发布、封杀、融资、事故）
- **解释型**：「这对你意味着什么」——把技术语言翻译成人话
- **预测型**：基于历史数据做一个可对答案的预测（如 Codex 额度重置窗口）。这类完播和互动最高，但**必须明说是预测**

## 3. 选输出模式（路由表）

| 模式 | 产出 | 适用 | 时长/篇幅 |
|---|---|---|---|
| `meme` | 梗概念卡 + 1–3 张整活图 + 字幕文案 | **默认优先考虑**。蹭电影/赛事/热歌/爆火梗 | 一眼看懂 |
| `meme-video` | 梗概念卡 + 15–30 秒视频提示词（arcloop） | 动作本身是梗（骑乘/对决/翻车） | 15–30 秒 |
| `flash` | 1 张图 + 60–120 字文案 + 标签 | 微博/群/朋友圈/即刻，追速度 | 一眼看完 |
| `xhs` | 封面 + 3–4 内页 + 正文 + 标签 | 小红书，追收藏 | 正文 300–800 字 |
| `douyin` | 口播稿 + 分镜表 + 视觉提示词 | 抖音/视频号，追完播 | 25–45 秒 |
| `image` | 生图提示词包（封面/卡片/九宫格） | **只出图不发视频**的场景（如热点预测、快讯海报） | — |
| `video` | 视频提示词包（按 arcloop 模型分版本） | 已有脚本，只要画面 | — |
| `full` | 以上全部 | 一条大新闻做全套 | — |

**默认建议**：**先判梗**。
- 能变梗 → `meme`（一张图，成本最低、试错最快）
- 梗里有动作 → `meme-video`
- 变不了梗、但事大 → `flash` 或 `xhs`
- 只有确定要稳定更新时才上 `douyin` + `video`（最费时、返工率最高）

**别为了「做视频」而做视频。** 平台看的是完成度和互动，不是形式。

## 4. 写文案：平台约束是硬的，不是建议

### 4.1 小红书（`xhs`）
- 标题 **≤20 字**，给 3 个备选，覆盖不同公式（数字合集/反差冲突/悬念警告/身份点名/利益承诺）
- 正文 **300–800 字**，超过 800 完读率断崖
- 段落 1–3 行一断，手机上不超过 4 段
- 开头三行定生死：直接给结果或抛冲突，**禁止**「大家好我是XX」
- emoji 每段 ≤1，全篇 ≤8
- **禁止输出 Markdown 加粗 `**`** 和 `#` 标题语法（小红书不渲染）
- 标签 5–8 个：2–3 大流量泛标签 + 2–3 精准垂类 + 1–2 自定义
- 结尾只给**一个**互动动作（收藏/提问/关注，选一个）
- 详细模板与失败案例见 `references/02-platform-xiaohongshu.md`

### 4.2 抖音 / 视频号（`douyin`）
- 前 3 秒必须有钩子，钩子必须和内容相关（纯标题党会限流）
- 语速按 **240–280 字/分钟**折算，脚本末尾标「全文 X 字，约 Y 秒」
- **每句 ≤15 字**，多短句
- 每 5–10 秒一个刺激点（新信息/转折/具体数字）
- 至少 2 处具体数字
- 输出分镜表：`时间 | 画面 | 口播 | 字幕/花字 | 备注`
- CTA 只给一个动作
- 详细模板见 `references/03-platform-douyin.md`

## 5. 做视觉：图先于视频（这条最重要）

**默认路径是「生图 → 出卡片/首帧 → 再决定要不要做视频」。**

> arcloop 站点迭代很快，动手前先看一眼生成器的模型下拉框：有些模型没有公开规格页（如 Nano Banana、Kling Omni），**不要为没有规格的模型写提示词**，按 `arcloop-models.md` §6 的「做不到清单」处理。

理由有三条：
1. 图上加中文，交给排版工具（Canva/醒图/PPT）比交给生图模型稳；生图模型画汉字十次错八次
2. 一张卡片图就能发，视频要 8 个镜头，成本差 10 倍
3. 图生视频时，首帧定了，视频只动不重画，出片率才高

### 5.1 生图（`image`）
- **默认路线 = 无字底图 + 后期加字**（路线 B）。只有「封面只有 4–10 字大标题且你愿意逐字校对」时才用一次出图带字（路线 A）
- **默认走「无字底图 + 后期加字」**：arcloop 的图片模型会自作主张加中文（官方实测会乱加标语、写坏标签）
- 六段式结构不能改顺序：主体 / 服装 / 构图 / 环境 / 光色 / **负面约束**
- **arcloop 没有负面词输入框**，负面约束必须内联进提示词末尾
- **3:4 图片侧不支持**：按 9:16 出图后裁切
- 用 GPT Image 2.5 Sunburst 出带字封面时：文案逐字列引号 + `no other text` + 100% 放大校对
- 详见 `references/04-image-prompts.md`

### 5.2 视频（`video`）
- **提示词写英文**（官方口径：镜头术语英文更成熟），画面里不出现任何文字
- **图生视频只描述运动**，不重复描述图里已有的东西
- 每镜**只给一种运镜**；必须写**显式端点**（`then comes to rest`），防 99% 卡死
- **短镜不写死秒数**：5–10s 镜头时长在下拉框选，提示词里写「0–3 秒」会出异常。**例外**：Seedance 2.5 一次生成 30s 时允许写 `0-8s / 8-18s` 分段（官方示例写法）
- **时长硬顶**：Seedance 2.5 = 30s；Seedance 2 / H3 系 = 15s；Vidu Q4 = 16s
- **图生视频用 Vidu Q4**（1 张起始帧）；**首尾帧只有 MiniMax H3 Max Turbo 支持**
- 口播用 **Seed Audio 1.0**，别指望视频模型自带人声
- 负面约束**内联**成最后一段，没有独立字段
- **矛盾约束自检**：同一条提示词里不许出现互斥约束（`no film grain` vs 要「胶片质感」、`no hands` vs 要「手部动作」、`no slow motion` vs 要「慢镜头」）。写完全片后逐镜对一遍
- 详见 `references/05-video-prompts.md` 与 `references/arcloop-models.md`

## 6. 去 AI 味：三句话版（吸收 shuorenhua，压到能执行）

改写时**只做减法，不做润色**。核心是「保住什么」比「删掉什么」更重要。

**必须保住**：事实、数字、谁做的、条件、范围、否定与情态、比较关系。
- 「成本降低 67%」不能写成「成本大幅下降」
- 「截至 10/20 尚未公布」不能写成「尚未公布」（丢掉时间锚点就变成了另一种断言）
- 「第三方转述」不能写成「官方确认」

**可以删**：纯招呼、致谢、没有具体内容的预告、不承担逻辑作用的填充、完整重复。
**可以降**：「完美融合」→「融合」，「极致的效率」→「很高的效率」。**但降夸饰需要授权**：只有用户明确说了「写平实点」「别吹」「去掉营销味」才降；只是「去 AI 味」「改狠一点」不算授权，默认保留原判断强度。
**不主动做**：不换同义词、不合并原词、不替作者把语气变自信、不在没依据时补实现方式或数据。

**AI 腔黑名单**（写完搜一遍）：
`作为 AI` · `总之` · `综上所述` · `值得注意的是` · `在当今时代` · `赋能` · `闭环` · `深度赋能` · `让我们` · `不仅仅是…更是…`

## 7. 事实纪律（翻车都翻在这里）

每条要发出去的事实，都要能回答「谁说的、什么时候说的、是官方还是转述」。

| tier | 含义 | 写的时候 |
|---|---|---|
| `official` | 厂商官方发布/官方博客/官方 X | 可以直接当事实写，最好带时间 |
| `first-party` | 同一方在多个渠道说 | 可以当事实写 |
| `third-party` | 媒体报道、评测机构 | 必须带主体：「据 XX 报道」「XX 评测」 |
| `unverified` | 单一转述、社区传闻、无出处 | **不写**，或明确写「有说法称，未获官方确认」 |

**如果一条官方源都没有**（只有媒体报道）：
- ✅ 可以发，但**每条事实都要带主体**：「据 The Verge 报道」「据 IT之家」
- ✅ 开头加一句来源披露：「目前公开信息来自媒体报道，官方尚未发布」
- ❌ 不许把媒体报道的细节写成确定事实（「据悉」「据报道」不能省）
- ❌ 只有 `unverified` 来源时**不发**，或明确写成「有说法称，未获官方确认」

**四条最容易犯的错**（都是实测踩过的）：
1. **把缺席当默认**：「没有公布许可证」≠「不会公布」。写成「截至 X 月 X 日，许可证信息未公布」
2. **把转述当官方**：「据 Testing Catalog 依据 API 文档称」不能被压缩成「支持 1M 上下文」
3. **两个口径并排当事实**：官方说「成本 1/3」、第三方说「定价一半」是两件事，分开归属
4. **自己算的数当原文**：汇率折算、增减幅计算出来的数字，要标「按…折算」

写完后跑：
```bash
python3 skills/ai-news-content/scripts/check_copy.py <输出文件> --material material.json
```

⚠️ **必须带 `--material`**。不带的话「数字溯源」这一项只会 WARN 通过，等于这道闸门关着。

它会检查：标题字数与备选数量、正文长度、`**`、emoji 数与分段、标签数量、CTA 是否只有一个、AI 腔黑名单、绝对化用语（硬/软两档）、站外导流、编造体感、AI 生成标识、以及**正文和标题里的数字是否都在素材卡里**（标题也会扫——标题是最高风险位置）。

## 8. 发布合规（不做会被限流/处罚）

- **AI 生成标识**：画面是 AI 生成的，必须在平台勾选 AI 生成声明，成片加角标。依据《人工智能生成合成内容标识办法》，2025-09-01 已施行
- **不做站外导流**：小红书别写「评论区扣 1 领入口」「私信我」；改成站内收藏/提问。真要给资源写「主页置顶整理」
- **绝对化用语**：「最强」「第一」「100%」「全网最低」属广告法高危词，改成「我见过的比较低的」「目前第一梯队」
- **不编造体验**：「我用了三个月」「实测爽到」——没用过就别写，评论区一次就拆穿
- 详见 `references/07-compliance.md`

## 9. 输出骨架（所有模式统一）

```markdown
# <日期> · <事件名>

## 0. 素材卡摘要
（来源、tier 分布、core facts 3 条、风险点）

## 1. <模式> 成品
（可直接复制发布的部分，放在代码块里，别夹私货）

## 2. 视觉提示词
（生图 / 视频，按平台分版本）

## 3. 发布前自检
（check_copy.py 输出 + 人工勾选表）

## 4. 风险与未确认
（哪些数字只有单一来源、哪些是预测、哪句话别写）
```

模板在 `assets/output-template.md`。

### 9.1 单文件还是拆文件（避免多人协作时各写各的）

| 场景 | 用法 | 文件命名 |
|---|---|---|
| 对话式一次性产出（最常见） | **单文件**，按上面 §9 五节写 | `<日期>-<事件>.md` |
| 批量 / 归档 / 多人接力 | **拆文件**，每个模式一个成品 + 视觉一个 | `00-素材卡摘要.md` `01-<模式>成品.md` `02-<视觉>提示词.md` |

拆文件时的三条规矩：
1. `00-素材卡摘要` 只写：来源、tier 分布、核心事实 3 条、筛掉哪些 unverified —— **它不是发布文案**
2. `01-*成品` 才是要发的东西，必须过 `check_copy.py` 全部项
3. `02-*提示词` 是技术产物，**不做数字溯源**（提示词里的色温 5600K、比例 9:16、模型版本 2.5 都不是事实）

> `check_copy.py` 已经按这个分工做了识别：文件名含「摘要/提示词/模板」自动走 generic 模式，只做通用合规检查，不查数字溯源。

## 10. 常见失败模式（自查表）

| 症状 | 原因 | 修法 |
|---|---|---|
| 稿子读起来像通稿 | 直接复述 AI 综述 | 换成「这对你意味着什么」的视角，加一个具体场景 |
| 评论区被质问数据 | 数字没标主体 | 每个数字加「据 X」，或删掉 |
| 视频生成出来糊字 | 提示词让模型画中文 | 画面零中文，文字后期贴 |
| 视频一半就卡住 | 没有显式端点 | 每镜补 `then settles / fades out` |
| 素材不够剪辑 | 口播比画面长 | 要么补镜，要么压口播，**不许用慢放凑**（会撞负面词） |
| 发出去没流量 | 标题自嗨 / 没有互动引导 | 标题换成读者视角；结尾只留一个动作 |
| 被判 AI 内容限流 | 没勾 AI 声明 | 发布页勾选 + 角标 |
