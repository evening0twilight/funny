## 总评

**不是「能不能用」，是「用了会以为自己做完了检查」。**

这个 skill 的内容层（选题判断、事实分层、arcloop 规格、合规）是我在这个仓库里见过最像样的，`arcloop-models.md` 那份规格书甚至比很多付费文档扎实。但它唯一的机器闸门 `check_copy.py` **是个橡皮图章**：

> 我把「全网最低价的最强模型，100% 不踩坑」写进标题，导出报「✅ 绝对化用语(硬) / ✅ 绝对化用语(软)」，结论是**全部通过，可以进入人工复核**。

更讽刺的是**你违反它的排版规则，反而会拿到更干净的报告**：在正文第一行加一句 `# 今天的大新闻`（SKILL 明令禁止 `#` 标题语法），检查器会把整段正文当成空、把 5 项检查降级成 WARN，剩下 12 项全绿。

**一句话结论：SKILL 可以拿去用，但最后一节的「check_copy.py 全绿（FAIL 一个都不能留）」这句话现在会骗人——在修好 §2 的 6 条 P0 之前，机器校验的通过结果不能作为发布依据。**

## 一、P0：一用就出事（附文件与行号）

### P0-1 `check_copy.py` 的小红书分支只扫正文，标题和标签完全不参与合规检查

`scripts/check_copy.py:173` 里 `check_xhs()` 末尾调用的是 `check_common(body, res)` —— 传的是**正文**，不是整篇。

于是 AI 腔 / 绝对化 / 站外导流 / 编造体感这 4 项，**对标题和标签两个字段是零覆盖**。而标题恰恰是小红书被投诉和限流的最高风险位置。

实测（样稿 `e3-absolute-title.md`，把标题换成绝对化三连）：

```
✅ 标题 ≤20 字                     3 个候选，长度 [19, 17, 16]
✅ 绝对化用语(硬)
✅ 绝对化用语(软)
✅ 站外导流
结论：全部通过，可以进入人工复核
```

标题原文：**「全网最低价的最强模型，100% 不踩坑」**——19 字，长度合规，「全网最低」「最强」「100%」三个词全部漏检。

同样地，把导流词塞进标签区（`#MiniMax #领入口 #扣1领教程`）也全绿，因为 `check_common` 看不到标签。

**改法**：`check_common` 的作用域应当是 `publish_scope(标题 + 封面文案 + 正文 + 标签)`。封面文案那一栏现在也是零覆盖。

### P0-2 正文里出现 `#` 标题行，检查器会把正文当空，整份报告变绿

`check_copy.py:56-64` 的 `section()` 用 `nxt = re.search(r"^#{1,3}\s|\n【", rest, re.M)` 找段落结尾——它把任何 Markdown 标题都当作「本段结束」。所以在正文第一行加一个 `# 今天的大新闻`，正文段被截断成空字符串。

而 `check_copy.py:151-156` 对空正文的处理是 `res.add(..., None, "没找到【正文】段落")` → WARN，**WARN 不算失败**（`check_copy.py:16` 明写「退出码：0 = 全过（WARN 不算失败）」）。

实测（样稿 `e1-hash.md`，正文内容与合格稿逐字相同，只在首行插了一行 `#`）：

```
✅ 标题 ≤20 字                     3 个候选，长度 [16, 17, 16]
⚠️  正文 300–800 字                 没找到【正文】段落      ← 长度规则自动失效
✅ 无 Markdown 加粗 **                                  ← 只查 **，不查 #
✅ emoji ≤8                     0 个                     ← 正文都没读到
✅ AI 腔黑名单                                          ← 正文都没读到
✅ 绝对化用语(硬)(软) / ✅ 站外导流 / ✅ 编造体感
✅ AI 生成标识
⚠️  数字可溯源                        未提供 --material，跳过
====================================================
结论：全部通过，可以进入人工复核
```

**12 个 ✅ 全部是空跑出来的。** 这比「漏检」严重：**违规操作会让检查器失去输入，然后它给你一张更干净的报告。**

**改法**：① 文本抽取前先剔除代码围栏和 `#` 行；② 段落为空必须是 FAIL 不是 WARN（找不到正文 = 这份文件不成立）；③ 增加一条「正文里禁止 `#` 标题语法」（`SKILL.md:99` 和 `references/02-platform-xiaohongshu.md:30` 都明令禁止，但一个字都没实现）。

### P0-3 数字溯源默认是关的，打开了也有两个大洞

**洞一：文档教的命令根本不带 `--material`。**

`SKILL.md:192` 写的是：

```bash
python3 skills/ai-news-content/scripts/check_copy.py <输出文件>
```

`check_copy.py:281-283`：没有 `material` 就直接 `res.add("数字可溯源", None, "未提供 --material，跳过")` → WARN → 通过。**SKILL 主入口只在这一个地方教了命令格式，而它是漏配参数的版本。** 对照 `references/06-fact-check.md:37` 和 `assets/output-template.md:150` 都带 `--material`，三处不一致，且主入口是最弱的那个。

实测：编一个「训练成本 4700 万元」写进正文，用 SKILL 的命令跑 → 全绿。

**洞二：即使带上 `--material`，还是漏。** 三处叠加：

1. `check_copy.py:269-273` 的 `_IGNORE_NUMS` 把 `0–10 / 16 / 20 / 24 / 30 / 60 / 100 / 1000` 全部豁免——「融资 5 亿美元」「22 家媒体」「15 万张卡」这类假数字天然放过；
2. `check_copy.py:298` 用 `n not in blob` 做**子串**匹配——素材卡里有 `0.22`，写「22」就命中；有 `0.15`，写「15」就命中；
3. 只查正文（`publish_text_of` → `section(text,"正文")`），标题、封面文案、分镜表的数字不查。

实测（样稿 `bad8-substring.md`，正文加两句假数字「据 22 家媒体报道，训练动用 15 万张卡」，素材卡用 test1 的真 `card.json`）：

```
✅ 数字可溯源                        全部命中
结论：全部通过，可以进入人工复核
```

**改法**：① `SKILL.md:192` 的命令补 `--material material.json`；② `_IGNORE_NUMS` 缩到「版本号 + 量词里的 1/2/3」；③ 子串匹配换成 token 集合匹配；④ 没有 `--material` 时应该是 FAIL 而不是 WARN（这是这个 skill 唯一的事实闸门）。

### P0-8 tier 分层把聚合站（AIHOT）的句子升成了 `official`，直接推翻 `00-sourcing-and-rights.md` 的核心结论

### P1-1 `04-image-prompts.md` §3：六段式把「风格」放第 5 段，紧接着的铁律却说「风格放最前」

```
1. 主体 … 2. 服装 … 3. 构图 … 4. 背景 … 5. 光色风格 …
```

同一屏里自相矛盾。如果「风格放最前」是真的（anti-drift 的常见经验），那六段式应该改成风格在第 1 或第 2 段；如果六段式是对的，那这条铁律写错了。**现在两条都在，运营只能猜。**

### P1-5 `03-platform-douyin.md:195` 编了一个不存在的技术理由

> 「慢放会撞剪辑软件的负面词/审核词，成片发不出去」

**慢放不会撞任何「审核词」。** 负面词是 AI 生成提示词里的概念，跟剪辑软件的导出审核无关。这条规则本身对（`SKILL.md:255`、`05-video-prompts.md:163` 都禁止慢放凑时长），但理由写错了，懂行的人一眼看出是编的。真实理由就两个：帧率不足会肉眼可见卡顿；画面长时间无变化会被判低质。

### P1-6 `assets/card-layouts.md` 的 9:16 → 3:4 裁切算错

`assets/card-layouts.md:218` 的坑位表：**「裁成 3:4 后标题被切 → 按 3:4 算安全区，上下各多留 10%」**

实际：9:16（1080×1920）裁到 3:4（1080×1440），上下各裁 240px = **各 12.5%**。

而且 `assets/card-layouts.md:12` 说「顶部 12% 会被平台 UI 吃掉」——两个 12% 量级的数字叠在一起，标题实际必须从 9:16 原图顶部 **24.5% 以下**才开始（12.5% 被裁掉 + 12% 被 UI 盖住）。文档写「上下各多留 10%」，会让标题上沿正好落在被裁的那一刀上，切掉 2.5%（约 36px）——刚好是一个字的上半截。**这个数字是后期排版唯一的坐标依据，10% 和 12.5% 的差别就是标题被切和没被切的差别。**

### P1-7 `SKILL.md:202` 推荐的改写结果，会被自己的检查器打 WARN

```
「最强」「第一」「100%」「全网最低」…改成「我见过的比较低的」「目前第一梯队」
```

`「目前第一梯队」` 含「第一」，命中 `check_copy.py:41` 的 `ABSOLUTE_SOFT` → WARN。实测：

```
⚠️  绝对化用语(软)                     出现 第一，确认有出处/归属再发
```

**更专业的问题**：「第一」→「第一梯队」是把**可核查的排名**换成了**不可核查的程度词**，这在合规上并没有变安全（无依据的程度词同样违规），却让读者更难验证。`shuorenhua` 原文（`skills/shuorenhua/SKILL.md:47`）明确要求「可核查的排名与首次（如『首个』『最常见』）照常保留」——这条在新 skill 里丢了。

**正确改法**：把「最强」换成「据 XX 榜单，它在 Y 项上第一」——保留可核查性，同时满足「有出处在才能用极限词」（`07-compliance.md:53` 本来就是这么写的，只是 `SKILL.md:202` 的示例写反了）。

### P1-8 `input-adapters.md` 的 schema 表漏了 `warnings` 字段；`SKILL.md` 全程不提 `license`

实测素材卡的顶层键有 20 个，`input-adapters.md:57-79` 的表只列了 19 个，**`warnings` 没写**（而 `--file` / `--url` 输入恰恰会往里写关键警告：「所有事实默认 unverified，发布前必须找到原始出处」）。

更重要的：`input-adapters.md:78` 说 `license` 是「**发布前必看**」，`license.commercial_ok` 实测返回 `requires_authorization`（AIHOT 数据对外商用要授权）。但 **`SKILL.md:261-275` 的发布前 11 项清单里没有任何一项关于商用授权**，`SKILL.md:198-204` 的合规节也没有。一个用 AIHOT 数据做商单的号，按 SKILL 走完全程不会看到这条。

另外 `warnings` 在真实卡里是 `[]`（空）——这条新闻明明有三个客观冲突（200T vs 56.7T+106T、1M vs 300K、人民币 vs 美元口径），`06-fact-check.md:27` 的「找矛盾」第 3 步完全靠人。**「warnings 字段存在但永不触发」是比没有更糟的设计**，会让人以为机器帮他查过矛盾了。

### P1-9 `shuorenhua` 的「降夸饰需要用户明确授权」这条前置条件在压缩时丢了

`shuorenhua/SKILL.md:40-44` 说得非常严格：

> 用户明确要求去掉宣传、吹捧或夸张的语气…**才额外允许**下面两种编辑。**只说去 AI 味、改狠一点、去套话…都不算这项授权。**

`SKILL.md:159` 把它压成了无条件规则：`**可以降**：「完美融合」→「融合」，「极致的效率」→「很高的效率」。` 前置授权条件、以及 `shuorenhua:47` 的「下列内容即使听起来很强也照常保留（承诺和保证、可核查的排名与首次、效果幅度）」全部消失。

后果：① 运营会在没人授权的情况下把「零停机」「首个」这类**可核查**的强表述削掉——这恰恰是 AI 资讯号最值钱的信息；② 它跟 P1-7 叠在一起，形成了「把可核查的排名降成模糊词」的完整错误链路。

**改法**：`SKILL.md` §6 补两行——「**降夸饰只在用户明确说『别吹/写平实点』时才做**」+「**可核查的排名、首次、效果幅度、承诺（零停机/无需改代码）即使很强也照常保留**」。

### P1-10 抖音没有发布文案和话题标签的产出物

`03-platform-douyin.md` 全文（含 §7 输出格式）只有：钩子 / 信息点 / 分镜表 / 口播全文 / BGM / 出镜。**没有抖音发布时的标题文案（信息流可见约 20–25 字）和话题标签（#）。** `assets/output-template.md` §1.2 也没有。

小红书有 3 个标题 + 标签 5–8 个，抖音一个都没有——**这是上一轮成品包就已经存在的缺口，合并重构后仍然没补。** 抖音发布页必须有文案和话题，否则运营拿到手还得现编。

### P1-11 `--all` 参数是死的，目录模式还会短路

- `check_copy.py:361` 定义了 `--all`，但 `:369` 是 `files = sorted(p.glob("*.md")) if p.is_dir() else [p]` —— 传目录就全跑，`--all` 完全没参与判断（`SKILL.md` 和 docstring 都在教 `--all`）。
- `check_copy.py:374` `ok = all(run_one(...) for f in files)` —— **`all()` 是短路的**。目录里第 1 个文件 FAIL，后面所有文件根本不会被检查，但结论只打一行「存在 FAIL，先改再发」。

实测（目录里放 3 个文件，第 1 个超长标题、第 3 个假数字）：

```
01-小红书图文.md  ·  mode=xhs
结论：存在 FAIL，先改再发        ← 02 和 03 的输出完全没有出现
```

修好 01 再跑，才会发现 03 的假数字。**多文件交付时这个 bug 会让「全绿」和「有 FAIL」都不可信。**

### P1-12 generic 模式没有走 `publish_scope()`，会把自己的反面教材判成违规

`check_copy.py:103-108` 的注释写得很清楚：

> 不做这层剥离，自检表里的「无扣 1 / 无导流」会被自己的检查器判成违规——这是典型的「检查器误报」，实测踩过。

然后 `check_copy.py:347` 的 generic 分支写的是 `check_common(text, res)`——**没走 `publish_scope()`**。于是同一个文件：文件名/标题格式让它判成 `xhs` 时全绿，改成 generic 时立刻 FAIL。

实测：把合格稿的 `### 【正文】` 改成 `### 【内容】`（内容一字未动），mode 掉到 generic，然后：

```
❌ 编造体感                         我用了、我实测
```

命中来源是它自己最后那张自检表的「无编造体感 | 无「我实测/我用了」」。**这份稿子的自检表反过来判它有罪。**

### P1-13 缺「系列化 / 数据复盘 / 评论区运营」

`SKILL.md:59-73` 的选题只有单条判断（三个问题 + 三种姿势），没有：栏目/系列设计（`03-platform-douyin.md:24` 提了「关注系列型」CTA，但没有栏目化方法）、发布后数据复盘（哪一项数据该看什么、什么时候该弃题）、评论区运营（置顶怎么写、负评怎么回、预测型怎么「回来对答案」）。这三块是「做号」和「写稿」的分界线，`README.md:98` 的文件结构里也没有位置。**属于「做号最需要但没覆盖」的部分。**
